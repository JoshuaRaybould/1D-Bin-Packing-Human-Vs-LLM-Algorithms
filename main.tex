\section{Introduction}

\subsection{Problem Background}

The bin packing problem (BPP) is one of the central problems in combinatorial optimisation. The basic setup is that we are given some number of items with corresponding values (generally size or weight) and we have access to as many bins as we desire, each with the same capacity. The goal is to find a way to pack the items into the bins such that we minimise the number of bins used. This is the one-dimensional (1D) bin packing problem which is very similar to the 1D cutting stock problem (\cite{maxence}). When it comes to the one-dimensional (1D) bin packing problem (which is what we will be handling), there are two main variants. First is the offline problem, where the algorithm being used has access to all items. Second is the online problem, where 1 item is given to the algorithm at a time, at which point it must decide where to place it, meaning it has access to less information. In this instance, we will be looking at the offline case.  

This problem falls into the category NP-Hard and it would take exponential time to arrive at the exact solution. For this reason, it is a good idea to use heuristic or randomised algorithms that don't generally give the exact solution but can obtain a near-optimal one efficiently. Other than being interesting due to its innate difficulty, bin packing also has many real-world applications, such as filling up trucks that have a weight capacity and in areas like cutting industries among others (\cite{munien}). Additionally, problems in scheduling often contain it as a special case. 

\subsection{Problem Definition}
Here we are looking at the classical (offline) 1D BPP. The following is a relatively standard definition arrived at with reference to \cite{munien}, though note often an equivalent normalised version is used (see: \cite{maxence}). Each bin has the same capacity c, and each item i takes on some weight/size $s_{i}$ such that $s_{i}$ $v \leq c$ c. First, define u to be an upper bound on the minimum number of bins needed to pack all n items. Use $y_{j}$ to represent whether we have opened the jth bin, with 1 $v \leq c$ j $v \leq c$ u. Specifically, $y_j$ = 1 if bin j is open (used) in the solution otherwise it is 0. Items are labeled with i, 1 $v \leq c$ i $v \leq c$ n and we introduce $x_{ij}$ to be 1 if item i is packed in bin j. Our goal is:
\[
\min\sum_{j=1}^{u} y_j 
\]
Minimise the number of bins opened. Subject to constraints:
\[
\begin{aligned}
\sum_{j=1}^{u} x_{ij} = 1, \quad \forall i = 1, \dots, n \\
\sum_{i=1}^{n} x_{ij} s_{i}  \leq C  , \quad \forall j = 1, \dots, u
\end{aligned}
\]
Which is to say that each item must be in one and only one bin and no bin can exceed capacity.

\subsection{Randomised Algorithms}
Randomised algorithms are those that use random numbers to influence their choices, therefore they are non-deterministic. We will define stochastic optimisation as being techniques and algorithms that make use of randomness to find a near optimal solution as in \cite{sean}. It should be noted however that the more common definition requires we have a noisy objective function and/or use random choices to direct the search for a solution, see . With the definition we use we can then say the algorithms we will implement belong to the field of stochastic optimisation and in most cases a subfield of it called metaheuristics. A metaheuristic is a problem-independent strategy which guides and modifies heuristics to arrive at better solutions (\cite{glover}, \cite{yang}). 

There are a very large number of randomised algorithms, which vary drastically in complexity. The simplest may involve using a naive algorithm and randomising the order of the input. This is useful if you suspect the order of the input may be poor for your algorithm, for example if it was produced by an adversary. On the other hand, there are complex metaheuristics which draw inspiration from evolution and organisms in general. Part of the goal of this paper is to cover a variety of these approaches.

\subsection{Large Language Models (LLMs)}
LLMs operate by predicting the most probable next token in a sequence, based on the context they have seen so far. The parameters of the model are obtained by a process of self-supervised learning on a large amount of training data. In this, they obtain an understanding of the meanings of words within sentences and the sentence structure, such that they can generate reasonable sentences (\cite{stryker}). Due to code being text like LLMs can also generate code.  

Naturally there are limitations; for example, the information they provide is not guaranteed to be correct and so needs verification. If the LLM is asked to produce something like what it saw in its training set, it is very likely to perform well, but it has no ability to reason beyond this (\cite{kucharavy}). This means for common programming tasks any of the popular LLMs (e.g. chatGPT, Gemini, Claude) will (generally) provide a reasonable response, but for niche problems they are much more likely to struggle. Whilst applying randomised algorithms to the bin packing problem is not a niche area, the specific ideas would not appear as frequently in the training set when compared to more general programming problems (e.g. those in the Mostly Basic Python Programming (MBPP) set of problems). Additionally, the algorithms require the tuning of parameters as well as more general design choices (e.g. should there be a local search phase in an implementation of ant colony optimisation) which could pose difficulties.

\subsection{Research Questions}
This project aims to compare a variety of randomised algorithms on the 1D offline BPP to implementations of those same algorithms generated by different LLMs. Specifically, our key research questions are: 
\begin{enumerate}
    \item How do a wide variety of randomised algorithms for the BPP compare in empirical performance on a variety of different instances? This will serve as a strong starting point for researchers interested in this area whilst also giving insight into how the algorithms perform in practice. 
    \item How effective are LLMs at producing correct and performant code for this kind of problem? Depending on this, we can then suggest ways in which LLMs can be used as tools when designing and implementing such algorithms.

\end{enumerate}

\section{The Algorithms}

\subsection{Best Fit With Randomised Order}
\subsubsection{Overview}
Best Fit is a very typical solution for the online version of the bin packing problem but isn't usually applied to the offline version (since there are better alternatives). It makes sense to start with this, as it is one of the simplest algorithms that could be applied to the problem that will still serve as a good baseline of performance. This will be the normal algorithm where the item is placed in the smallest available space it can fit into but with the order of the input items being randomised. The purpose of this is to allow the algorithm to (generally) do better when given bad orderings \cite{rajeev}.
\subsubsection{Time Complexity}
In all cases randomising the input using the Fisher-Yates shuffle requires O(n) operations. The best fit algorithm then runs. In the worst case each item is too large to fit in any open bin meaning the algorithm will on average search through n/2 bins before opening a new bin. This happens for all n items, hence O($n^2$). Therefore, the overall worst case time complexity is O($n^2$). 

\subsection{Simulated Annealing}
\subsubsection{Overview}
This is extremely similar to hill-climbing, which works like so:

Start with some candidate solution.

Repeat until we arrive at a local optimum or run out of time:
\begin{enumerate}
\item Alter the candidate solution slightly (move to a neighbouring solution).
\item If this altered solution is better than our current candidate solution, then 
select it to be our new candidate solution; otherwise, there is no change.
\end{enumerate}

The difference with simulated annealing is that rather than only selecting a new solution if it is better than the current candidate solution, it can with some probability choose to move to a worse solution. The purpose of this is to provide an opportunity to escape a local optimum, increasing the chance of finding and converging at the global optimum. This probability depends partially on a temperature value; the higher this is the more likely the algorithm is to move to worse solutions. The temperature decreases as the algorithm progresses on a schedule we decide. For this algorithm and most beyond this, my main sources to gain general understanding are Sean Luke's Essentials of Metaheuristics and Gendreau and Potvin's Handbook of Metaheuristics (\cite{sean}, \cite{gendreau}).

\subsubsection{Implementation}
Firstly, the initial candidate solution is generated by using a first fit decreasing (FFD) algorithm as Sonuç, Sen and Bayir do here (\cite{sonuc}). We also use the same objective function and their ideas for moving from a candidate solution to a neighbouring one (note these are quite common ideas, see for example: \cite{kryz}). Specifically, the objective function will be:
\[
\max\sum_{j=1}^{u} \sum_{i=1}^{n} {(x_{ij} s_{i})}^{2}
\]
In the actual implementation this is divided by bin capacity. Note that we can improve this function without decreasing the number of bins used, but it effectively directs the algorithm towards solutions where the bins are as full as possible. To move to a neighbouring solution, we select two different bins (a and b) at random. Then we decide whether we will move an item from bin a to bin b or if we will swap items between them. There will be an equal chance of either happening and the items to move will also be selected at random. If the move/swap would lead the solution to violate a constraint then the candidate solution remains unchanged.

Moreover, we need to define the general parameters present in simulated annealing. We set temperature = 1000000 and decide on using an exponential cooling schedule with our  $\alpha$ = 0.995. This schedule was chosen as it was more effective than a linear cooling schedule, likely due to its slower cooling allowing for more exploration (see \cite{algafter} for more about cooling schedules). This value for $\alpha$ is large, but using one lower than this meant it was uncommon for solutions to actually be improved in terms of bins due FFD being relatively strong (see \cite{dosa}  where it is shown that the solution FFD comes to is at worst $\tfrac{11}{9}$ times the optimal plus $\tfrac{6}{9}$).

\subsubsection{Time Complexity}

First we obtain the initial candidate solution with FFD, this requires O(nlogn) for sorting the items in reverse order, then first fit is carried out. There are n items and in the worst case for each item no open bin can hold it and so it will check n/2 bins on average before opening a new one, giving O(n * n/2). \subsection{Tabu Search}

\subsubsection{Overview}

Tabu search was proposed to help tackle the problem of local search methods getting stuck in local optima. It is effectively a local search, working similarly to hill climbing except it stores the best solution found so far and maintains a list of recently visited candidate solutions. This list is called the tabu list and solutions in it cannot be returned to. Provided a sufficiently large list this means if a local optimum is reached then the algorithm will move away from it and be unable to return to it. This allows the algorithm to explore the space more, giving greater opportunity to find stronger solutions. 

\subsubsection{Implementation}

We use FFD to obtain the initial candidate solution as we do in our simulated annealing implementation and also use the same objective function. Tweaking our solution to obtain a neighbouring one is also done similarly here; we pick 2 random bins and then either swap two random items between them or move a random item from one to the other. A slight difference here is that when moving a single item 60\% of the time we move it from the least full bin (lowest weight), since it is much more likely to become empty, so is likely to lead to a strong neighbour (this is true in practice). The idea of targeting a specific bin comes from \cite{lodi}. We carry out 10,000 iterations and during each generate 40 neighbours and select the best which doesn’t violate our tabu list. Note that this can lead to a worse solution, but we ensure we always have the best found solution stored. We set the tabu list to have a length of 8, as setting it greater than this led to no benefit but slowed the algorithm. Rather than storing entire solutions in the tabu list, we store the bins that were changed to prevent them from returning to that configuration. This has a very similar effect but is less computationally intensive than storing the entire solution. The tabu list is ignored only in the case that a bin can be eliminated, that is to say a bin can return to a previous configuration provided this allows for the removal of a bin. 

\subsection{Grouping Genetic Algorithm}

\subsubsection{Overview}

The genetic algorithm (GA) is a population-based method and takes ideas from genetics and evolution, so classes as an Evolutionary Algorithm (EA). In general, there is an initial population of individuals. These individuals will be encodings of potential problem solutions (commonly bit strings). These should be able to be handled better by the algorithm. Each individual has a fitness determined by a fitness function. This information is used to inform breeding, then a new population is formed consisting of the children, or sometimes also some parents.  

Generally, the genetic algorithm takes a desired population size and generates a population of that size consisting of randomly generated individuals (chromosomes). The ideal population size is problem dependent, if it is too small then there will not be enough variety in the population to explore the search space sufficiently but too large and it will run too slowly. Next, the algorithm repeatedly selects an individual from the population based on some strategy and applies crossover and/or mutation to it. The specifics on this vary, it can be guaranteed that both crossover and mutation happen or that each happen with some probability etc.  The selection method is most often tournament selection - which effectively takes a tournament size t as input and selects the best of t randomly chosen individuals from the population based on fitness (note that the selection does not remove the individual from the population). If our individuals are bit strings, then crossover could be carried out by swapping some bits between two individuals (parents); mutating an individual would flip bits within it with some probability. Once the selected individual has been altered, it is added to a new population. Once the new population reaches the set population size it is then used in the process of building another new population. This continues until we reach a termination condition, which is often after a certain amount of time. Our final solution is then the highest fitness solution in the population we arrived at.  

There are many ways this algorithm can be slightly altered, one of relevance here is elitism. Rather than building the new population entirely via the process detailed before, we instead select some number, n, of individuals we wish to keep from the current population. These will be the fittest n individuals, referred to as elites.  

The following is heavily informed by Falkenauer's work here \cite{gga}, including some general parts of how we go on to implement the algorithm. Unfortunately, the BPP is a grouping problem which GAs don't tend to perform well on. There are a few reasons for this, such as mutation operators generally being ineffective, poor encodings meaning crossover is much less useful etc. For these reasons, the normal GA requires modifications to become a competitive algorithm for the problem. Specifically, we will be implementing a grouping genetic algorithm (GGA). In brief, the core difference is that we will focus on whole groups at a time rather than dealing with each item like you would in a GA. This means that the encoding must contain reference to each of the groups and so we must allow for variable size chromosomes. For example, if we have groups labelled A, B, C then it could be that one chromosome only uses A and B so includes AB, but another uses all 3 so would include ABC.  

\subsubsection{Implementation}
The encoding used takes Falkenauer's idea, we have two parts, the first is an array with each index corresponding to an item. The value at an index i is the bin which item i belongs to. The second part is a dictionary where the keys are the group labels and these correspond to a list of the items i in that group. The population size is set to 20 (note this is a relatively small compared to general GA populations but handling more means a large time trade off) and the initial population is generated by performing a first fit after randomising the input order as this should provide good variety. We carry out 60 iterations, so go through 60 new populations total. Assessing fitness is done as in our implementation of simulated annealing. We make use of elitism, selecting just the best of the current population to add to the next. 

When it comes to crossover we use two point crossover, where you pick a start and end index at random, then these and every group between these is swapped between the two parents crossover is being applied to. In doing this, items that already have groups in the parent (and are not being swapped out) may appear again in a group that has been swapped into this parent so must be removed from its previous group and the first part of the encoding updated. Most of the time some items will be left unassigned since it is unlikely the groups being swapped contain the exact same items, so FFD is applied to ensure every item has a group again. Crossover is time consuming and so is only applied 10\% of the time. Mutation simply removes a group at random then applies FFD to the items.

\subsection{Ant Colony Optimisation}

\subsubsection{Overview}

The first use of ACO was under the name Ant System (AS) and was used for the travelling salesman problem (TSP) though its effectiveness was limited to small instances. There have also been many improvements to the algorithm over time, e.g. Elitist AS, MAX-MIN AS (MMAS) (see \cite{stuetzle}) and Rank-based AS to name a few, which make it very competitive, as noted by Levine (\cite{levine}).  

Ant Colony Optimisation (ACO) is a popular metaheuristic for combinatorial optimisation. Whilst in realilty it is only very loosely based on actual ant behaviour it was inspired by it. Real ants leave behind pheromones when travelling, which other ants will follow. If we provide ants with two different paths between their nest and a specific food source, whilst at first their behaviour is random, over time they tend towards the short path. This is because those which pick the short path will arrive back at the nest first, and so there will be more pheromones on the short path. The ants then become much more likely to pick the short path due to the higher level of pheromone, which in turn leads to more pheromone and so eventually the entire colony picks the short path. 

The algorithm naturally lends itself to the TSP and so I will explain it in terms of that here. Some amount of pheromone $\tau(i, j)$ is associated with the edge between cities i and j. Generally, the pheromone can be thought of as relating to the quality of that specific component of the solution. We have a population of ants and put each ant in a random city; they are then left to visit each city once. Each ant has associated memory used to store the solution so far (so it starts with just the initial city and builds an entire solution).  To decide which city j an ant k in city i moves to next the following equation is used: 

\[
p_k(i,j) =
\begin{cases}
\dfrac{[\tau(i,j)]^{\alpha}[\eta(i,j)]^{\beta}}
{\sum\limits_{c \in C_k(i)} [\tau(i,c)]^{\alpha} [\eta(i,c)]^{\beta}} & \text{if } j \in C_k(i), \\[10pt]
0 & \text{otherwise}.
\end{cases}
\]

Here $\eta(i, j)$ is a heuristic we define, $\alpha$ and $\beta$ control the importance of the pheromone and the heuristic respectively. $C_k(i)$ is the set of cities that still have to be visited by ant k which is in city i - in the general case this is the set of feasible components which can currently be added to the solution. Note that the equation differs slightly from Levine’s by including $\alpha$, this is relatively standard, see (\cite{aaron}, \cite{gendreau}). Once each ant has arrived at a complete solution, the pheromone on each edge is updated. Each ant can be thought to have a limited value of pheromone which is spread equally across the length it travelled, therefore if it went a shorter length the pheromone it left would be denser. Each iteration some pheromone will also evaporate; this is determined by $\rho$. 


\subsubsection{implementation}
The parameters were chosen using Levine’s work \cite{levine} as a guide. We found that using a population of ants tied to the number of items, n, was effective, specifically choosing a size of 0.8 x n. The heuristic value used for an item is that item’s weight. The evaporation parameter p was set to 0.95 with the heuristic importance $\alpha$ = 2 and pheromone importance $\beta$ = 5, though so long as these were above 1, performance was relatively consistent across values tried. We use pheromone scores between item weights, for example if an item of size x and an item of size y frequently appear in good solutions then the pheromone value between x and y will be high. To get the pheromone value for a specific item j being put in a specific bin b we use the following equation from Levine: 

\[
\tau_b(j) =
\begin{cases}
\dfrac{1}{|b|}\sum_{i \in b} \tau(i,j) & \text{if } b \neq \varnothing\\[10pt]
1 & \text{otherwise}.
\end{cases}
\]

This effectively means that if in a good solution item j tends to pair with the items already in bin b then item j should have higher probability of being added to bin b. If no item can fit in the last opened bin, then b must be a new bin we open, in this case it does not matter what item is chosen and so the pheromone score will be 1 independent of the item. When updating the pheromone value between weights based off of a solution, we first multiply the value by the evaporation parameter (0.95 here). Then add the product of the number of appearances of the specific weight pair in the solution and the fitness of the solution. Fitness is determined by the same objective function used in our simulated annealing implementation (the sum of squared bin weights divided by the total weight of all items). (TODO: this originally came from Faulknauer, so credit somewhere). 

We use some ideas from MMAS by Stuetzle and Hoos (\cite{stuetzle}) (the same used by Levine). The first is that in each iteration only the best ant (the one with highest fitness) found in that iteration places pheromone, and that every $\gamma$ iterations the best ant found so far is used. We set $\gamma$ to be 500/n. This value is important because it effectively determines the balance between exploration and exploitation, with low values leading to rapid reinforcement of the best components and so less opportunity for exploration. The second idea we take requires defining minimum and maximum possible pheromone values ($\tau_{\min}$ and $\tau_{\max}$ respectively), which we do using the formula arrived at by Stuetzle and Hoos: 

\[
\tau_{\max} =
\frac{p} {1-p}\\[10pt]
\]

\[
\tau_{\min} =
\frac{\tau_{\max}\left(1 - \sqrt[n]{pbest}\right)} {(avg - 1)\sqrt[n]{pbest}}\\[10pt]
\]

Here, pbest is the probability of constructing the best solution after every pheromone value has converged to $\tau_{\min}$ or $\tau_{\max}$. Note however that this is only an approximation since if a set of items are put into a bin the order in which this happens does not affect the outcome which interferes with the mathematics carried out to arrive at the above equation for $\tau_{\min}$. Additionally, $\tau_{\max}$ cannot be used as a maximum since certain pairs of weights can appear more times in a solution than others – so will be reinforced more. We set pbest to 0.05, and when updating the pheromone value for a component if the value falls below $\tau_{\min}$ it is set to $\tau_{\min}$. The final idea we take from MMAS is the use of optimistic initial pheromone values, specifically setting each to $\tau_{\max}$.
