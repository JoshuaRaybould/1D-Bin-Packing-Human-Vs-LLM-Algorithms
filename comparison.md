## Comparing Algorithms 

### 1. Best Fit With Randomised Order 

Best Fit is a very typical solution for the online version of the bin packing problem but isn't usually applied to the offline version (since there are better alternatives). The reason that I chose to start with this is that it is one of the simplest algorithms that could be applied to the problem that will still be able to serve as a good baseline of performance. This will be the normal algorithm where the item is placed in the smallest available space it can fit into but with the order of the inputs being randomised. The purpose of this is to allow the algorithm to (generally) do better when given bad orderings.

#### Time and Space Complexity

Randomising the input requires O(n) operations since the algorithm iterates through each index i in the input list, and on each iteration an index j is chosen at random such that i ≤ j < len(input) before swapping the values at indexes i and j. The best fit algorithm then runs. In the worst case each item is too large to fit in any open bin meaning the algorithm will on average search through n/2 bins before opening a new bin. This happens for all n items, so approximately n/2 x n = n^2/2 hence O(n^2). Therefore, the overall worst case time complexity is O(n^2)

### 2. Simulated Annealing

This is extremely similar to hill-climbing, which works like so: 1) Start with some candidate solution. 2) Alter the candidate solution slightly (move to a neighbouring solution). 3) If this altered solution is better than our current candidate solution then select it to be our new candidate solution otherwise there is no change. Repeat steps 2 and 3 until we arrive at a local optimum or run out of time. The difference with simulated annealing is that rather than only selecting a new solution if it is better than the current candidate solution it can with some probability choose to move to a worse solution. The purpose of this is to provide an opportunity to escape a local optimum, increasing the chance of finding the global optimum. The probability with which it moves to a new solution depends partially on a temperature value, the higher this is the more likely the algorithm to move to worse solutions. The temperature decreases as the algorithm progresses.

The important things to determine here are what should the initial candidate solution be, how should we alter the candidate solution to arrive at a neighbour, and how should temperature be handled in terms of starting value and being decreased over time. For the initial candidate solution it makes sense to use something relatively simple such as applying first fit decreasing to the problem and using the packing it arrives at. To alter the solution we will randomly pick 2 different bins, at which point we have 3 options which we choose from at random: (1,1) pick an item from each bin at random and swap them, (1,0) pick an item from the first bin at random and move it to the second bin, and (0,1) pick an item from the second bin at random and move it to the first bin. In each case if the swap is not possible then nothing will happen.
